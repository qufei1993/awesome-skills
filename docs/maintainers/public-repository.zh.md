# 公开仓库维护

[英文版](public-repository.md)

## 更改可见性之前

合并面向公众的文档和许可证改动，确认其他正在进行的发布工作已经结束。检查所有分支、标签和可达历史中的凭据与非公开资料，不能只检查当前文件。不要将部署密钥复制到仓库文件中。

MIT 许可证适用于原创代码和原创文档。保留第三方内容的许可与署名记录；未知许可状态不能作为已获授权的依据。

## 仓库公开时的 GitHub 设置

部分 GitHub 功能受仓库可见性和套餐限制。更改可见性后，应用并回读确认以下设置：

- 使用规则集或分支保护保护 `main`。要求通过 PR 合并，且 `validate` 和 `publish-readiness` 检查成功。要求讨论已解决，禁止强制推送和删除分支。
- 有其他维护者时，要求另一位维护者审核。仅有一位维护者时，不要设置无法自行满足的自我审批要求。
- 在 Actions 设置中，要求所有外部贡献者的工作流运行先获得批准。默认工作流令牌保持只读，禁止 Actions 批准 PR。
- 不向 Fork PR 提供云端部署密钥。现有 `pull_request` 工作流为 Fork 生成可下载的预览包，仅同仓库分支可以部署云端预览。不要改为通过具有高权限的 `pull_request_target` 工作流执行提案代码。

设置完成后，用 Fork PR 验证：运行先等待批准，校验能产出预览包，云端部署被跳过。确认失败的必需检查会阻止合并。

## 目录与发布状态

根目录 README 是源码收录目录，不是发布状态报告。预览构建不得向目录添加审核标签。实际审核与核验状态保留在生成数据中。审核后合并 PR 代表同意发布，不代表安装或工作流已通过实测。

仓库修改运行 `npm run check`。发布数据与更改仓库可见性是两项独立操作。
